# Restaurant Management System — Frontend

Admin dashboard, point of sale, and customer-facing ordering pages for a restaurant, built with React and TypeScript. The UI is Arabic-first (RTL) and talks to a separate **Laravel REST API**.

> The backend lives in its own repository. This repo contains the frontend only.

## Features

**Operations**
- Point of sale (POS) with modifiers, and an offline queue that syncs orders when the connection returns
- Orders, kitchen display screen, and order alerts
- Tables and floor plan, with a QR code per table (print one or all)
- Reservations, including no-show handling
- Deliveries and driver assignment
- Cash drawer: shifts, withdrawals and deposits, closing

**Management**
- Menu: categories, items, and modifier groups
- Inventory with stock tracking and restocking
- Customers, loyalty, and favorites
- Payments, refunds, coupons, and customer reviews
- Expenses and multi-currency support
- Staff, roles, and per-user permissions
- Workforce: schedules, attendance, and payroll with payslips
- Reports and an end-of-day Z-Report (PDF and CSV export)
- Audit log and notifications

**Customers (public, no login)**
- QR menu per table: `/t/:token`
- Online ordering: `/order`
- Order tracking: `/track/:token`

Every admin page is protected by permission checks, so each user only sees what their role allows.

## Tech stack

- [React 19](https://react.dev) + TypeScript

- [Tailwind CSS v4](https://tailwindcss.com) and [Radix UI](https://www.radix-ui.com) primitives

- [Recharts](https://recharts.org), [Framer Motion](https://www.framer.com/motion/), [Axios](https://axios-http.com)

## Getting started

### Requirements

- Node.js 20.19+ or 22.12+
- The Laravel backend running locally (default: `http://localhost:8000`)

### Install and run

```bash
npm install
npm run dev
```

The dev server proxies `/api` to `http://localhost:8000` (see `vite.config.ts`). If your backend runs elsewhere, change the proxy `target` there.

### Environment variables

Copy the example file if you need to override the API address:

```bash
cp .env.example .env
```

| Variable | Description |
| --- | --- |
| `VITE_API_URL` | Full URL of the backend API, e.g. `https://api.example.com/api`. Leave it **unset** in development so the Vite proxy is used. An empty value (`VITE_API_URL=`) breaks the connection. |

### Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the dev server |
| `npm run build` | Type-check and build for production (`dist/`) |
| `npm run preview` | Preview the production build locally |
| `npm run lint` | Lint with Oxlint |

## Project structure

```
src/
├── api/          Axios client and one module per backend resource
├── components/   Shared components and UI primitives (shadcn-style)
├── features/     One folder per page/domain (pos, orders, kitchen, reports, ...)
├── hooks/        Reusable hooks (permissions, printing invoices, offline sync, ...)
├── layouts/      Admin shell: sidebar, topbar, command palette
├── lib/          Utilities (formatting, QR, downloads, offline queue, ...)
├── routes/       Router, protected routes, permission gates, navigation config
├── stores/       Zustand stores (auth, settings, offline queue)
└── types/        Shared TypeScript types
```

The `@` import alias points to `src/`.

## Notes

- **PDFs are generated by the backend.** The frontend only downloads or opens the file it receives (invoices, payslips, Z-Report, report exports).
- **Authentication** uses a bearer token sent with every request. A `401` response clears the session and redirects to `/login`.
- **Deployment:** it is a single-page app, so the static host must redirect unknown paths to `index.html`. Build with `npm run build` and serve `dist/`.
